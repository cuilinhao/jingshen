# Mac 与真机验收清单

以下是**待在 Apple 环境执行**的验收，不是已通过记录。

## 构建与离线

| 步骤 | 预期 |
|---|---|
| 单独解压新版，双击其中的 xcodeproj | PGYDepthDemo Scheme 可见，源码与样片无红色缺失引用 |
| 检查 App Target → Build Phases | 只有 Sources / Frameworks / Resources；没有模型下载阶段 |
| 已安装完整 SDK 后，在 Mac 断网环境做不签名构建 | 无外部依赖请求；没有 Hugging Face 相关错误 |
| 真机全新安装，断网首次处理本地清晰照片 | 系统主体路径可用时能识别；没有外部模型下载请求 |
| 检查当前路径提示 | 必须区分“系统主体虚化”和“局部虚化”；局部路径成功不等于系统识别验收通过 |
| 用只在 iCloud 的照片测试 | 可能需要系统取回原图；改用已在本机的文件进行离线验收 |
| 模拟器或系统请求失败 | 能导入并显示局部虚化提示，能继续调整/导出，而不是阻止使用 |

## 交互与显示

| 测试 | 预期 |
|---|---|
| 参考画布 402×874；不同尺寸设备 | 主画布等比居中，非同宽高比屏幕允许留边 |
| 黑底、顶部圆按钮、底部胶囊、独立导出、橙红对焦框 | 与录屏的主界面布局比对；需要实际截图，不能用参考帧充当运行截图 |
| 左右连续拖动光圈 | 指针固定、刻度移动；大 f 值更弱，f16 为零虚化 |
| 点主体 A，再点主体 B | 若系统区分了二者，清晰主体切换；不能仅看框移动，需要检查图像像素 |
| 点背景 | 背景清晰，已识别前景虚化；不承诺每个背景物体都有独立焦平面 |
| 识别把两个对象合并为一组 | 作为一组处理，不伪造两个独立深度 |
| 查看蒙版 | 主体/局部模式：白色虚化、黑色清晰；原生深度模式：亮近暗远 |
| 关闭效果 / 长按对比 / 开关蒙版 | 不改变原始输入；对比时保持相同裁切 |
| 竖图、横图、极宽图、旋转/镜像 EXIF | 焦点、蒙版与画面不应翻转或错位；黑边点击不生效 |
| 裁切后点击，再切回原始比例 | 焦点正确映射到原图；没有在已裁切成图上重复编辑 |
| 换图同时快速拖动/点选 | 旧任务不得覆盖新图片 |

## 算法边界

用人物、杯子、透明瓶子、玻璃、发丝、电线、细碎叶子、低对比主体、多个相邻物体、无明显主体的风景分别测。记录系统识别内容与渲染边缘问题，不能把画质失败统称为“网络问题”。

明确局部模式要验证圆形选区在横图和竖图上不拉伸、范围可调、圆外真实发生模糊。不能把局部圆形效果描述为已识别完整物体。

前景虚化、背景虚化分别看边缘光晕、颜色渗入、细线丢失和旧轮廓残留。本版本没有遮挡补全，这些场景不保证达到原软件画质。

## 草稿与导出

| 测试 | 预期 |
|---|---|
| 调焦点/光圈/裁切/色调后保存，杀进程再打开 | 参数和照片恢复，成功的主体蒙版可从缓存恢复 |
| 从上一版 v1 草稿升级 | 保留原图与配方；旧外部模型缓存不伪装成原生深度 |
| 分析缓存损坏但原图/配方正常 | 重新分析，不丢失原图和配方 |
| 无保存相册权限 | 明确报错，仍可通过系统分享存储到文件 |
| 导出横图/竖图/小图 | 最长边≤2048、小图不放大、无控件/对焦框/GPS |
| f1.4 与 f16、切换两个主体的导出对比 | 输出效果与预览方向一致，而不是固定同一张图 |
| 连续编辑后导出 | 从原始处理输入重建，不累积反复模糊 |
| 存储空间不足 | 明确错误，完整的上一个草稿指针不被半写文件替代 |

## 自动测试

`swift test`：核心数学、主体选择/背景反选、局部蒙版、配方版本、草稿读写与迁移。

`python3 -m unittest discover -s Tests -p 'test_*.py'`：工程离线依赖与文件归属等静态检查。Python 仅用于可选检查，不是 App 依赖。

Xcode **⌘U**：上述核心测试，加上 11 项 Apple SDK 图像测试（像素读取、裁切、滤镜参数、效果关闭、局部模糊、像素缓冲区、系统请求失败回退、缓存复用/拒绝错尺寸）。失败回退测试注入固定失败分析器，不声称验证了真实 Vision 识别。

用 Instruments 记录目标 iPhone 的首次识别耗时、峰值内存、拖动延迟与导出时间。未实测前不要填写预估值为测试结果。
