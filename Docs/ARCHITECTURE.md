# v5 人物选择景深架构

## 分析和存储

`PhotoSession` 同时包含深度 `PhotoAnalysis` 和可选的 `PortraitAnalysis`。前者回答相对远近，后者保存每个人的独立软蒙版。`selectedPersonID` 放在 v5 `EditRecipe`，不编码进深度场。

`PhotoPipeline.prepare` 先归一化 EXIF 方向并准备最长边 2048 的处理输入。原生辅助深度优先；否则校验 `InferredDepth` 缓存的源 SHA256、尺寸、模型 ID、预处理 ID 和深度变化，无有效缓存才推理。人物分析独立校验源 SHA256、尺寸及分割版本，无有效缓存才调用 Vision；人物失败不冒充选择成功，而是提示后继续普通景深。

`NativeSubjectSegmenter` 使用 `VNGeneratePersonInstanceMaskRequest` 及每个实例的 `generateScaledMaskForImage`，最多接受四个独立实例。面部检测用于发现部分拥挤或不完整结果，但无法证明已找齐所有人；背身、遮挡或实例合并仍需人工验证。普通合并人像蒙版不能满足同距离两人单独选择。

整图结果之后，`PersonRegionDetector` 在全图和 3×3 重叠窗口检测上半身框，输入最长边为 1536。不同尺度的框映回左上原图坐标并去重；大框不能仅凭包含关系吞掉小框。已有蒙版未覆盖的目标按人体框 1.3 倍裁切，等比采样至最长边 768，再用 `.accurate` 人像语义分割找回像素轮廓；统一局部输入尺度可减少小人头部附近椅框误归属。框只定位、不直接充当蒙版；局部结果映射回原图，清理一次，再扣除已有人物，并保留目标头部附近的连通软区域。

每个补充结果都是独立蒙版，`PersonMaskAssembly` 统一重编号并重建标签，避免不同 Vision 请求复用同一 ID。最终人数仍限制 1–4；分割缓存升级到多尺度 v3，使旧的单主体缓存重新分析。小人物核心如果被粗网格漏采样，锚点与焦深从高分辨率核心密采样兜底；焦深取原深度图，不从检测框或人物编号猜测。

原始 coverage 在分析阶段按原图尺度只清理一次：以 ≥230/255 为可靠核心，32…230 平滑映射到 0…1；离核心 4…8 像素（按最长边 1024 等比换算，最小比例 0.25）逐渐衰减。这样保留贴近主体的软边，并去掉较远的弱背景残影。没有可靠核心的结果不作为可选人物；全部失败则回退普通景深。点击、轮廓、背景剔除与人物合成共用清理后的蒙版；分割缓存版本升级使旧草稿自动重新分割，深度缓存独立保留。

`SavedDraft` 原子保存源数据、类型化深度、可选人物分析与 v5 配方。人物 ID 仅在该次分割中有效；复用经校验缓存可恢复原 ID，重新分割则依据保存的原图焦点重新匹配。旧草稿仍可迁移，失效缓存只触发重算，不丢失原图和参数。

## 两种模型合同

| 项目 | 默认 V3 Base | 对照 V2 Small |
|---|---|---|
| 输入 | RGB 504×504 | RGB 518×392 |
| 几何 | 等比缩放、居中补边 | 原有全图缩放 |
| 输出 | Float16 `depth` / `confidence` 数组 `[1,504,504]` | Float16 灰度 `depth` 图 |
| 深度转换 | 去补边后取倒数 | 使用原输出方向 |
| 最终场 | 有效内容 p1/p99 归一化，0…1 亮近暗远 | p1/p99 归一化，0…1 亮近暗远 |

两模型内部已处理 RGB255 归一化；App 不重复标准化输入。V3 补边颜色为 ImageNet 均值，使用同一整数 ROI 生成输入和裁去输出补边，补边不参与分位数统计。每次输出检查尺寸、有限值和非恒定变化。

`MLMultiArray` 必须按实际 strides 读取。Mac 探针中 V3 加速输出 strides 是 `[258048,512,1]`，与连续数组不同。`confidence` 是未标定输出，不当作概率使用，当前渲染不依赖它。

两份 `.mlpackage` 均只加入 Xcode Sources，由 Xcode 原生编译。App 仅加载 Bundle `.mlmodelc`，没有运行时下载或编译。模型选择保存在配方中，V2/V3 的缓存身份分开。真机使用 `.all`，模拟器 `.cpuOnly`，加速失败有 CPU 尝试；实机内存与时间仍需测量。

## 选择与分层合成

屏幕点击经过 aspect-fit 和裁切逆映射到原图坐标，再检查高分辨率人物软蒙版。单人自动选中；多人默认选择覆盖面积最大的人；空白点击保留选择。焦深优先从选中人物内部可靠区域取中值，避免把肩膀外背景作为焦深。

人物模式中，选中人物虚化量为零，其他人具有虚化下限，背景仍按连续深度虚化。合成前从背景颜色中剔除所有人物，并在有限范围向内延展背景色，减少人物颜色被背景虚化带出的光晕。这是边缘补色，不是生成或重建真实遮挡内容。

人物层采用 RGBAh / linear-sRGB，将原始颜色乘以清理后的 coverage。Vision coverage 不是物理透明度，不能拿它和估计背景反解前景颜色；旧的背景相减会在黑发、手腕等处产生色块。失焦层在原图范围外先延展再模糊，防止贴边身体透明化。人物使用软 alpha，按远到近合成；失焦人物的颜色和 alpha 一起扩散。因此前景仍遮挡背景，即使背景中的人被选中。选中轮廓只用于预览反馈。无人物或局部模式保留原有普通景深路径。

人物模式的背景使用两档 `CIBokehBlur`，由连续深度控制混合，保留圆形高光与灯带的大体形状。只对不透明背景采用 power=3、模糊后 power=1/3 的高光响应，人物颜色与 alpha 不参与该变换。这是接近参考效果的艺术化散景近似，不是标定过的镜头成像或真实遮挡重建。

缓存与图片会话、人物选择、参数和渲染尺寸绑定；图片或分析变化创建新会话身份。准备数据可跨点击复用，换人和光圈不触发模型分析。预览最长边 1024，导出从最长边 2048 的处理原图重新渲染，半径随尺寸缩放；原图不累积虚化。

## 并发和验证边界

重处理由串行 actor 执行，UI 使用导入/渲染版本令牌，避免旧任务覆盖新选择。同步 Core ML 推理不能保证即时取消，重步骤前后检查取消状态。

纯 Swift 测试覆盖选择、层序、几何、缓存和草稿；Apple SDK 测试覆盖像素与真实模型适配；Mac 独立探针补充输出方向/stride 证据。合成图通过不能证明 Vision 能准确分出真实发丝；桌面耗时不能代表手机性能。当前执行结果统一记录于 [VERIFICATION.md](VERIFICATION.md)。

人物边缘保留原图颜色，因此细发丝、半透明接触边缘仍可能带有原背景色；人物整体深度排序不支持交叉肢体的逐像素遮挡重建。清理阈值已在一张用户样片中验证，不能证明所有人物、衣物与背景条件下都合适。这些属于后续真实样片验收范围。
